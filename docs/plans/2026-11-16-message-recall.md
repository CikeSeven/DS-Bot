# 撤回消息

- 日期：2026-11-16
- 相关：无 Issue；代码在 `ds-bot/src/host/recall.js`、`src/client/user-message.js`、`mobile_flutter/lib/features/chat/chat_page.dart`

## 为什么

用户发错了消息、发给了不该发的 Bot，或者想换个问法重来时，没有办法把已经发出的消息收回：Bot 的私聊就是它的 DSH 会话，会话日志只追加，发出去的消息和 Bot 的回答会一直留在 Bot 的上下文里。

社区已经有几个做「回溯」的 DSH 插件（`dsh-recall-plugin`、`@jochenyang/dsh-rewind-plugin`、`@kangyishuai/dsh-session-rewind`），但都不能直接给 DS Bot 用：

- 它们的撤回按钮挂在 DSH 自己的用户消息气泡上，DS Bot 用自己的气泡替换了它，按钮不会出现。
- `sessions.fork` 的做法会换一个会话 id，而 DS Bot 按会话 id 记每个 Bot 的分段、卡片、定时任务和搜索索引。
- 它们只有网页界面，手机 App 用不上。

DS Bot 自己实现，用的是 DSH 自己的表面替换（`Session.append` 的 `surfaceOp: { op: 'replace' }`，压缩也用它）：日志一条不删，只追加一个事件，把一段历史移出模型能看到的范围。不改 DSH，也不照搬这些插件的代码。

## 已定的行为

### 能撤回什么

- Bot 私聊里用户自己发的消息，在 Bot 的当前分段里，而且还在 Bot 的上下文里。没有时间限制。
- 不能撤回：群聊里的消息、更早分段里的消息、Bot 自己的回答、其他 Bot 的来信、运行在本地 Agent CLI 上的 Bot 的消息（CLI 自己保存一份对话）、已经被压缩进 checkpoint 的消息。
- 还在队列里、Bot 没开始处理的消息，照旧在队列栏里改或删。

### 撤回做了什么

- 回溯：这条消息和它之后的全部内容（Bot 的回答、工具调用、Bot 之间的往来）离开 Bot 的上下文，也从聊天里消失。原处留一行「你撤回了一条消息」。
- 原文放回发起撤回的那台设备的输入框。输入框里已经有草稿时接在草稿后面，不覆盖。图片和文件不放回。
- 会话日志不删事件：追加一条 `user/message`（来源 `ds-bot-recall`），`surfaceOp` 从被撤回的消息替换到上下文末尾。模型在那里读到一句说明：用户收回了这里之后的消息和对它们的回答，当它们没发过。用户接着发的消息和这句说明会在同一个请求里，所以说明只讲收回了什么，不对下一条消息提要求。紧挨着上一次撤回的说明再撤回时，替换从上一句说明开始，上下文里只留一句。
- `state.json` 的 `recalls[分段]` 记下每次撤回的范围：被撤回的消息（`seq`、所在的轮次 `turn`、它是否开启了这一轮 `opened`）、占位事件（`until`）、范围到达的最后一轮（`last`）。电脑界面、手机聊天、聊天预览、搜索索引、`read_own_chat`、换分段的交接内容和记忆整理都按它跳过这一段。
- Bot 正在干活时，先停下这一轮。排队的输入不丢：撤回进行中开始的回合会被挡住，输入放回队列，撤回完成后接着处理。
- 这段范围里还在等用户的提问卡、视图卡一起关掉。
- 撤回之后其他设备通过 feed 的 `recall` 事件重新读聊天。

### 文件

- 不恢复文件，也不撤销 Bot 做过的事。
- 撤回前先查这条消息之后 Bot 改过的文件：已经结束的轮次读 DSH `workspaceChanges` 的改动摘要，还没结束或摘要已经不在的轮次看有没有写文件的工具调用。
- 改过文件时提示一次：改了几个文件、前几个文件名、撤回不会还原它们，用户确认后才撤回。没改过文件时不提示，直接撤回。

### 电脑端

- 鼠标停在自己的消息上，撤回按钮和复制按钮一起出现；触屏上和复制按钮一样常显。
- DSH 没有 `projectUserText` 时（例如 0.2.2-alpha.2），用户气泡由 DSH 自己画，DS Bot 用样式改成自己的样子。DS Bot 的条目借用 DSH 用户条目的语言和 `inject`，在自己的条目里原样画 DSH 的组件，把撤回按钮放进气泡的操作行（复制所在的那一行）。DSH 的用户子插槽只能有一个主人，所以 Bot 聊天里它的「消息来源」位（只有 liveshare 插件用）不再渲染，和 DSH 自己的中途插话行一样。
- 中途插进来的消息（steering）以前没有操作行，现在和普通消息一样悬停出现复制和撤回；还没被 Bot 读到的插话气泡仍然没有。
- DSH 有 `projectUserText` 时，气泡由 DS Bot 自己画，撤回按钮同样在复制旁边。
- 需要提示时，提示卡出现在气泡下面，有「取消」和「撤回」。

### 手机端

- 长按自己的消息，菜单最后是「撤回」，只对当前分段里的消息出现。需要提示时弹确认。
- 接口见[移动端客户端 API](2026-10-24-mobile-api.md)「撤回消息」。

## 不做什么

- 不做群聊里的撤回。
- 不恢复文件，不撤销 Bot 已经做的事（发出的消息、派出去的活、对外的操作）。
- 不提供「只撤回这一条、保留之后的对话」。
- 不改 DSH。

## 已知限制

- 已经压缩进 checkpoint 的消息不能撤回；撤回只在当前分段里，换分段时已经写进交接笔记的内容不受影响。
- 撤回前 Bot 已经存进记忆的内容、已经发给其他 Bot 的消息和派出去的活不会跟着撤回，其他 Bot 的回复照常送回。
- DS Bot 不自己画的 DSH 原生行（比如重试提示、轮末的文件改动卡片）只按整轮隐藏：被撤回的消息是 Bot 干活中途插进来的那一轮，这类行仍会显示。
- 在 DSH 自己的气泡上，撤回按钮靠 DSH 组件的类名（`_userRow`、`_actions`）找到操作行；DSH 改了这些类名，按钮就不出现，和 DS Bot 现有的气泡样式一样需要跟着改。
- 占位说明是一条用户角色的消息，模型知道用户收回了一段对话。
- 旧版手机 App 不认识 `recalled` 条目。
